# Object physics and visual masking components

Reviewed: 2026-09-24. Implementation revision: `fe746e2`.

The clarified user scope is **component support**, not concrete objects or box placement. `scripts/physics/collision_parts_2d.gd` accepts caller-authored `Shape2D` resources and clones them into separate solid `CollisionShape2D` or sensor `Area2D` parts. Callers own body type, motion, mass, shape dimensions, offsets and collision channels. Deferred toggles are safe from overlap callbacks. No magnet behavior, scrap/bin scene, scoring, timer, automatic mask-to-shape conversion or hard-coded game collision profile exists.

`scripts/physics/visual_mask_2d.gd` plus `shaders/occlusion_mask.gdshader` provide independent visual occlusion. Alpha 1 hides target pixels, alpha 0 preserves them; outside the mask rectangle is unmodified. The centered mask's world transform supports translation, rotation and scale, updated on transform/property changes. Sampling is nearest without repeat. A missing/disabled/singular-transform mask is inactive. Shader changes affect only the target sprite's alpha; source texture RGB, modulate and existing alpha are preserved. No collision object is touched.

Binding owns one sprite material, restores its predecessor on detach, and uses a fresh ShaderMaterial per component. Restrict targets to the same world canvas/viewport and one mask per target. It does not combine custom shaders, infer occlusion ordering, accumulate multiple masks or mask whole scene trees. Callers explicitly select the art hidden behind each occluder. Diagnostic fixtures borrow the contributor's alpha mask without turning it into final gameplay collision geometry.

`labs/physics/` demonstrates independent visual, solid and sensor state. Its authored boxes are test fixtures only. `tests/physics_parts_test.gd` verifies real engine ray/overlap behavior, shape-resource isolation, independent toggles and material restoration. `labs/capture physics` additionally checks actual GPU alpha before/after masking and translation, and observes contact/sensor events. The source relies on Godot's [CanvasItem shader COLOR and MODEL_MATRIX contracts](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html) and [CollisionObject2D filtering](https://docs.godotengine.org/en/stable/classes/class_collisionobject2d.html); local 4.7 checks establish compatibility. This is no gameplay acceptance or performance claim.

2026-09-24 verification: the complete `tests/check` suite passed on an isolated, byte-matched source snapshot because a contributor's interactive lab held the original checkout's runner lock. GPU mask checks and inspected captures passed at 1920×1080, 1280×720, 960×540 and 854×480 with Godot 4.7 / NVIDIA GeForce RTX 2080 Ti. Each run observed a solid contact and sensor entries while alpha clipping remained independent. Concrete objects, dynamic rigid-body magnet handling, multiple occluders, touch and gamepad behavior remain unverified/deferred.
